# Git 커밋 정책

GitHub에 올리는 커밋 메시지와 PR 제목·설명은 한국어로 작성합니다. 코드 식별자나 제품명처럼 번역하면 혼동되는 고유 표기는 원문을 유지할 수 있습니다.

커밋은 하나의 기능, 수정, 설정 등 검토 가능한 작업 단위로 나눕니다. 코드의 개별 함수마다 커밋을 만들지는 않으며, 서로 무관한 변경을 한 커밋에 섞지 않습니다.

## 분류

| 접두어 | 사용 기준 | 예시 |
| --------- | --------------------------------------------------------- | ---------------------------------------- |
| `Add:` | 새 기능, 파일, 설정, 문서를 더할 때 | `추가: OCI 배포 안내 문서 작성` |
| `Delete:` | 기존 기능, 파일, 설정을 제거할 때 | `삭제: 사용하지 않는 개발 스크립트 제거` |
| `Update:` | 기존 동작·설정·문서를 고치거나 오류를 바로잡을 때 | `수정: API 오류 응답 형식 통일` |
| `Etc:` | 위 분류로 설명하기 어려운 정리, 도구, 의존성 작업을 할 때 | `그외: 패키지 검사 명령 정리` |

표의 접두어는 작업 분류를 나타냅니다. 실제 커밋 제목과 PR 제목·설명은 예시처럼 한국어로 작성하고, 변경의 주된 목적에 맞는 분류 하나를 고릅니다. 커밋 제목은 변경 결과가 드러나도록 짧고 구체적으로 씁니다.

## 보안 및 검토

`.env`, 비밀번호, API 키, SSH 개인키, `node_modules`, 빌드 결과물, 생성된 Prisma Client, 로컬 캐시는 커밋하지 않습니다. 커밋 전 `git status`와 변경 내용을 확인하고, 관련 검증 결과를 PR 설명에 한국어로 기록합니다.
